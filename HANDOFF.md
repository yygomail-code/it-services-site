## Согласованные решения
| Вопрос | Решение |
|---|---|
| Фронт | Angular standalone, mobile-first, prerender → чистый HTML |
| Бэк | PHP 8.5.x — шлюз лидов + API админки |
| Мессенджеры | НЕ подключаем (только почта; задел — интерфейс `Notifier`) |
| БД | MariaDB 11.4 (совместима с MySQL) |
| Админка | `/admin`: лиды, страницы, медиатека, формы, пользователи, роли, контакты, футер, бренд, подвал |
| Воронки | Клиентская (услуги) + партнёрская (/partners, 7 ролей) |
| Уведомления | Письма (заявки и уведомления пользователям) ставятся в очередь `email_queue` ДО отправки: при сбое SMTP повторы 5/10/15/20 мин (до 5), затем статус failed + кнопка «Отправить ещё раз» в админке. Обработка: заходы в админку (троттлинг 5 мин), вручную, cron `api/cron_email_queue.php` или ссылка с ключом из админки (для планировщиков, умеющих только URL). Отправленные старше 30 дней удаляются |
| Хостинг | Виртуальный сервер: PHP + MySQL + статика, без Node |
| Роли | Настраиваются в админке (`roles`). Все базовые роли (Гость, Пользователь, Менеджер, Администратор) — **системные**: удалить нельзя, код не меняется (название и порядок — можно). Добавленные роли редактируются и удаляются; при смене кода ссылки в настройках обновляются, при удалении — убираются |
| Почтовые сервисы | Раздел «Почта»: SMTP-подключения (Яндекс, Mail.ru, Google, свой) с назначением (заявки, регистрация, действия, покупки, прочее), проверкой тестовым письмом. Пароль в API не отдаётся (`has_password`), пустой при сохранении — «не менять» |
| Пользователи | Профиль: логин, пароль, ФИО, дата рождения, страна/регион/город/адрес, телефон, почта, Макс, Телеграм, Ватсап, сайт, роль, состояние (активен/заблокирован), аватар из медиатеки, комментарий. Системные учётки (admin, manager1, `is_system=1`): блокировать и удалять нельзя — переименовать, сменить пароль и профиль можно. Заблокированный войти не может (403). Уведомления на email: при создании (логин + пароль) и смене пароля — через активный сервис «Почты» (`mailerFindService`, fallback — любой активный) |
| Единый стиль форм | Шапка раздела: заголовок слева, кнопки справа, описание под заголовком (`.admin-section__header`); у контента снят лимит 1280px. Формы (настройки, редактор формы, пользователи) и модалка медиафайла — строки «подпись 170px + поле на всю ширину», кнопки в шапке справа |
| Видимость ссылок | У каждой ссылки колонок футера — набор ролей (чекбоксы). Пусто = скрыта для всех; не задано = видна всем; новая ссылка = все роли. Выбраны все роли — сохраняется как «без ограничений» |
| Доступ к страницам | У страницы — набор ролей (как у ссылок). Гость на закрытой странице видит заглушку «доступна после входа» с кнопкой «Войти» (возврат на страницу после входа); вошедший без роли — заглушку «Нет доступа»; обе с `noindex`; контент закрытых страниц в prerender не попадает |
| Мигание при загрузке | Элементы с ролями не рендерятся до проверки сессии (`AuthService.ready`) — чужие пункты не мелькают; элементы без ограничений видны сразу |
| Шапка сайта | Раздел «Хеадер»: подпись у логотипа (с «Крупнее»), меню (текст/ссылка/порядок/видимость по ролям), кнопка. Логотип и название — из «Бренда». Отдельной кнопки входа нет — «Вход» добавляется пунктом меню (например, /login или /admin, видимость «Гость») |
| Бренд | `brand.name`, `brand.mark`, `brand.logo` — единый источник для шапки сайта, футера и админки |
| Prerender | Контент из БД попадает в статический HTML (сборка обращается к API через `PRERENDER_API_BASE`) |
| Редактор страниц | Канвас в стиле Notion (TipTap): правка на месте, «+»/«/» для вставки, ⠿ для перетаскивания, поповеры настроек, Ctrl+Z, авто-черновик в localStorage. Поток блоков + контейнер «Секция» (фон/отступы/выравнивание/колонки); хранение в БД и рендер сайта не меняются (конвертация в канвасе) |
| Контент страниц | Все публичные страницы собираются в редакторе (включая главную, «Портфолио»). Каталоги услуг и кейсов подключаются блоками «Услуги»/«Кейсы» (карточки услуг — из БД, кейсов — из данных сайта; у кейсов — лимит показа и фильтр по категориям). У заголовков доступен H1; у секций — фон «Градиент (как hero)» |
| Модуль «Услуги» | Каталог услуг/товаров живёт в БД и управляется в админке (`/admin/services`). Страницы `/services` и `/services/:slug` принадлежат модулю (не редактору). Шаблоны карточек — варианты вёрстки (какие поля и в каком порядке); календарь записи — один общий (схема готова к нескольким мастерам); комментарии — с пре-модерацией. Дефолты: слоты 30 мин, оплата — только фиксация способа (онлайн-платежей нет), менеджер может скрыть/удалить комментарий. Этапы: 1) каталог+админка+публичные страницы — готов; 2) рейтинг и комментарии; 3) календарь записи; 4) регистрация и личный кабинет; 5) магазин |

## Что сделано
- **Модуль «Запись» (этап 3) — ядро готово и проверено сценариями**. Схема `db/migrate_bookings.sql`: таблица `bookings` (номер `BK-XXXXXX`, слот `slot_at`/`slot_end`, буферы на момент записи, клиент, статусы `new|confirmed|done|canceled|no_show`, отмена (`cancel_reason`, `canceled_by`, `canceled_at`), оплата (`payment_status|method|amount|paid_at`), токен отмены, UTM) + настройки `booking.schedule` (дни/часы/шаг), `booking.horizon_days` (30), `booking.min_hours_ahead` (2). Тестовые данные: старые 11 услуг и товары удалены (восстановление — `db/seed_services.sql`), залиты 6 тестовых услуг с записью `db/seed_services_booking.sql` (30/45/60/90 мин, буферы 0–15, авто/ручное подтверждение, предоплата/постоплата, разные способы оплаты). API `api/bookings.php`: публичные `slots` (расписание + буферы + занятость по ВСЕМ услугам — мастер один; горизонт; минимум за 2 ч; выходные), `create` (валидация, `GET_LOCK` против гонок, повторная проверка слота, защита от дубля по телефону, авто-статус по `auto_confirm`, письма в `email_queue`), `item`/`cancel` по токену из письма; админские `list` (фильтры: статус/поиск/даты/услуга, пагинация, счётчики new/сегодня), `admin_item`, `status` (подтверждение/отмена/выполнено/не пришёл, `canceled_by`), `payment` (статус/способ/сумма, `paid_at`), `reschedule`, `schedule`/`schedule_save`. Проверено сценарным тестом (`%TEMP%\opencode\booking-scenarios.php`, все OK): слоты (16 на день, суббота — выходной, прошедшие недоступны, за горизонтом — ошибка), авто-подтверждение, занятость слота, параллельные записи (другая услуга/то же время → 409 «занято»; тот же клиент/то же время → 409), буферы 15/15 (13:30/14:00/15:00 заняты, 15:30 свободно), отмена клиентом по ссылке (неверный токен 404, повторная отмена 409, слот освободился), подтверждение/отмена админом (canceled_by=admin), оплата (paid/card/2000/paid_at), перенос (старый слот свободен, новый занят), валидация (422), письма в очереди (leads/actions), список в админке. **Осталось по модулю: публичный UI (календарь на карточке услуги + страница `/booking/:id?token=` для отмены), админ-раздел «Записи» (список + настройки расписания), затем улучшения по результатам**
- **Сортировка ссылок в шапке, футере и подвале — исправлена (найдена причина)**. Симптом: в админке порядок сохраняется (в БД верный), но на сайте ссылки шли в старом порядке. Причина: контент из БД грузился **после** старта приложения — при гидратации клиент видел дефолтное меню/пустой футер, расходился с prerender-HTML, Angular пропускал компоненты и DOM-порядок ломался. Исправления: (1) `src/main.ts` — контент загружается **до** `bootstrapApplication` (`setPreloadedContent` в `ContentService`, затем обычные запросы), первый рендер совпадает с prerender; (2) шаблоны шапки/футера переписаны без `@if` внутри `@for` — один `<a>` с условными привязками (`routerLink`/`href`/`target`/`rel`), колонки футера фильтруются геттером `visibleColumns`, контакты — один `<a>` с `[class.footer__work]` и `[style.display]` у иконки; (3) в разделе «Подвал» добавлены кнопки **↑/↓** (`moveLink`), раньше сортировки не было вовсе. Проверено сквозным тестом (админка → сайт): «Товары» в шапке вниз/вверх, ссылка в колонке футера, ссылка подвала — порядок на сайте совпадает с админкой; сборка 27 маршрутов
- **Аудит сайта и админки + улучшения клиентского опыта (P0)**. Составлен `AUDIT.md`: инвентаризация, аудит клиентского пути и админки, целевая модель «ядро + модули» (контракт модуля: флаг `modules.<id>.enabled`, `api/<id>.php`, таблицы `<id>_*`, один админ-раздел и один пункт меню, публичные маршруты с 404 при выключении), дорожная карта (P1 «Модули», P2 запись, P3 корзина/заказы, P4 отзывы/промо/оплата) и правила «без перегруза». Внедрено и проверено CDP: **страница 404** (`/404`-контент: заголовок, ссылки на разделы, `noindex`; маршрут `**` → `NotFoundComponent`, серверный режим — Client); **живой поиск в каталоге** (задержка 350 мс, Enter — сразу, `replaceUrl` — без мусора в истории, кнопка «Найти» убрана, «Сбросить» сбрасывает поиск/группу/сортировку); **липкая мобильная панель на карточке** услуги/товара (≤900px: «Оставить заявку» — плавная прокрутка к форме `#lead-form`, «Позвонить» — `tel:` из «Контактов», `env(safe-area-inset-bottom)`); **хлебные крошки в каталоге** («Главная / Услуги»); **группы в админ-меню** («Работа» — Лиды, Каталог; «Контент» — Страницы, Медиатека, Формы; «Система» — Пользователи, Роли, Почта; «Сайт» — Контакты, Хеадер, Футер, Бренд, Подвал). Проверено: 404 (h1/ссылки/noindex/title), поиск (11 → 1 «CRM-системы» → сброс 11, URL `?q=crm`), панель (`display:flex`, низ экрана 755–844 из 844, `tel:+79094981322`, прокрутка scrollY 0 → 880), метки меню. Сборка: 27 маршрутов
- **Админ-список каталога: поиск и фильтры без кнопки «Найти»** — живой поиск (задержка 350 мс, `OnDestroy` чистит таймер), фильтры по типу и группе применяются сразу. Проверено CDP: кнопки нет; «crm» → 1 строка «CRM-системы», очистка → 11; «Товары» → 0, «Все» → 11. **Шаблоны карточек: поиск, фильтр по типу и сортировка** (А–Я, Я–А, по количеству полей больше/меньше) — проверено CDP на 2 шаблонах (тип «Только товары» → «Карточка товара»; по полям 7 → 10 и 10 → 7; пустой поиск — своя заглушка)
- **Модуль «Каталог» (услуги и товары) — этап 1 (каталог, админка, публичные страницы)**. Схема: `db/migrate_services.sql` — таблицы `service_categories` (группы), `card_templates` (шаблоны карточек: `fields` — JSON порядка и видимости полей), `services` (цена/префикс «от»/примечание, единица `piece|time` + длительность, буферы до/после, адрес и координаты, флаги: календарь, магазин, комментарии, рейтинг, автоподтверждение, пред/постоплата, способы оплаты, роли доступа, SEO-поля), `service_media`; настройки раздела `services.enabled` и `services.roles` в `app_settings`. Каталог из старого `services.data.ts` перенесён сидом `db/seed_services.sql` (11 услуг). API `api/services.php`: публичные `catalog` (поиск, группы, тип, запись, пагинация, фильтр по ролям, обложки), `item` (медиа, шаблон, `restricted`), `categories`; админские `admin_list`/`admin_item`/`save`/`delete`/`categories_admin`/`category_save`/`category_delete`/`templates`/`template_save`/`template_delete`/`section`/`section_save` (CSRF, `requireRole(['admin','manager'])`). Админка: `/admin/services` — «Каталог услуг и товаров» (список с фильтрами, карточки «Раздел "Услуги" активен на сайте» и «Раздел "Товары" активен на сайте» — вкл/выкл + доступ по ролям), `/admin/services/new|:id` (все поля, медиа-галерея с обложкой, доступ по ролям, SEO), `/admin/service-categories` (группы каталога), `/admin/service-templates` (конструктор полей карточки), пункт меню «Каталог» (admin+manager).
