# AUDIT.md — аудит сайта и админки, модель «ядро + модули»

Дата: 2026-09-17. Составлен по итогам развития модуля «Каталог» (услуги и товары).
Цель: упростить клиентский путь (запись, покупка, корзина, доставка/самовывоз) и
заложить ядро, к которому модули подключаются и управляются без перегруза.

## 1. Что уже есть

**Публично**
- `/` — главная (редактор страниц), `/services`, `/products` (отключаемый раздел), карточки
  `/services/:slug`, `/products/:slug` (галерея, цена, оплата, карта, форма заявки),
  `/portfolio`, `/portfolio/:slug`, статические страницы (about, partners, contacts,
  policy, terms, cookie-policy, `/pages/:slug`), `/login`, `/profile` (заглушка).
- Prerender 27 маршрутов (роботы видят контент), SEO: meta, canonical, JSON-LD
  (Organization, Person, Service, Product), sitemap.xml, robots.txt, cookie-баннер.

**Админка** (роли admin/manager)
- 13 разделов: Лиды, Каталог (услуги и товары, группы, шаблоны карточек), Страницы
  (канвас-редактор), Медиатека, Формы, Пользователи, Роли, Почта (SMTP + очередь писем),
  Контакты, Хеадер, Футер, Бренд, Подвал.
- Лиды: фильтры, поиск, статусы, удаление; письма не теряются (очередь `email_queue`).
- Каталог: разделы вкл/выкл + доступ по ролям; группы с типом (услуги/товары/общие);
  шаблоны карточек (порядок и состав полей); медиа-галереи; лимиты, пагинация, живой поиск.

**Технически**
- Angular 22 (standalone, zoneless, prerender) + PHP 8.5 (экшен-роутеры `api/*.php`) + MariaDB.
- 18 API-файлов, 17 таблиц; `app_settings` — настройки (включая флаги разделов).

**Чего нет (по целям пользователя)**
- Записи на услуги (календарь, слоты, подтверждение, кабинет клиента).
- Корзины и покупки товаров, заказов, статусов заказа.
- Доставки/самовывоза, вариантов получения услуги (адрес/удалённо/выезд).
- Отзывов, рейтинга, комментариев; онлайн-оплаты; промокодов.

## 2. Клиентский путь: что мешает и что улучшить

| Шаг | Проблема | Улучшение |
|---|---|---|
| Главная → каталог | Карточки услуг ведут только на страницу | Быстрые действия на карточке: «Заявка»/«Записаться» (после модуля записи) |
| Каталог | Кнопка «Найти» — лишний шаг; нет хлебных крошек | Живой поиск (сделано), крошки, «сбросить фильтры» |
| Карточка услуги | На мобильном форма внизу — надо долго листать | Липкая нижняя панель «Оставить заявку» + «Позвонить» (сделано) |
| Заявка | Нет подтверждения «что дальше» на отдельной странице | Оставить inline-успех; добавить письмо-подтверждение клиенту |
| Товары | Нет покупки: раздел выключен, корзины нет | Модуль «Корзина и заказы»: drawer-корзина, чекаут в 1 шаг |
| Запись | Нет календаря и слотов | Модуль «Запись»: услуга → дата → слот → подтверждение |
| Получение | Нет вариантов (самовывоз/доставка/адрес/выезд/удалённо) | Поле «способ получения» в заказе и записи + справочник вариантов |
| 404 | Неизвестный адрес молча ведёт на главную | Страница 404 с подсказками (сделано) |
| SEO | sitemap.xml статический | Генерация sitemap из БД на сборке (позже) |
| Доверие | Нет отзывов | Модуль «Отзывы и рейтинг» (пре-модерация) |

## 3. Админка: что упростить

- **Навигация перегружена** (13 пунктов одним списком) → группы: Работа (Лиды, Каталог),
  Контент (Страницы, Медиатека, Формы), Система (Почта, Пользователи, Роли),
  Сайт (Контакты, Хеадер, Футер, Бренд, Подвал) — сделано.
- **Настройки размазаны**: флаги разделов живут в «Каталоге», видимость — в шапке/футере.
  Решение: страница **«Модули»** — единая точка «что включено на сайте» (см. §4).
- **Родственные разделы**: Хеадер/Футер/Подвал/Бренд/Контакты — со временем свести в
  «Сайт» с вкладками (шапка, подвал, бренд, контакты) — уменьшит число пунктов.
- Нет журнала действий (кто менял) — не критично, но полезно при нескольких менеджерах.

## 4. Целевая модель: ядро + модули

**Ядро** (не отключается): страницы/контент, медиатека, формы и лиды, пользователи/роли,
почта и очередь писем, SEO, настройки сайта (шапка/подвал/бренд/контакты), редактор страниц.

**Модуль** — самостоятельный блок с единым контрактом:
1. **Идентификатор** (`catalog`, `booking`, `orders`, `reviews`…) и **флаг включения**
   `modules.<id>.enabled` в `app_settings` (как сейчас `services.enabled`/`products.enabled`).
2. **API**: `api/<id>.php` — экшен-роутер (`action=…`), CSRF, `requireRole`.
3. **Таблицы**: префикс `<id>_*` (или явные таблицы, как `services`).
4. **Админ-раздел**: `admin/<id>/*`, один пункт в меню (вложенное — внутри раздела).
5. **Публичные маршруты**: `/<id>` и `/<id>/:slug`; выключенный модуль отдаёт 404 и
   скрывает пункт меню (как уже сделано для товаров).
6. **Настройки и уведомления**: письма только через `email_queue`; доступ — через роли.

**Управление без перегруза**
- Страница **«Модули»** в админке: карточки модулей (название, описание, статус
  «готов/в разработке», вкл/выкл, ссылка на раздел). Одна точка включения.
- Админ-меню строится из реестра: выключенный модуль не показывается (кроме ядра).
- Публичное меню — из настроек шапки; в редакторе ссылок модули уже доступны списком.

**Реестр модулей (план)**
| Модуль | Статус | Что даёт |
|---|---|---|
| catalog | готов | услуги и товары: каталог, карточки, группы, шаблоны |
| leads | готов | заявки с форм + очередь писем |
| pages / media / forms / users / mail | готовы | ядро |
| **booking** | план | запись: календарь, слоты с буферами, подтверждение, кабинет |
| **orders** | план | корзина, заказ, доставка/самовывоз, статусы, письма |
| **reviews** | план | отзывы и рейтинг с пре-модерацией |
| delivery | внутри orders | способы получения (самовывоз, доставка, адрес, выезд, удалённо) |
| payments | внутри orders | фиксация способа и пред/постоплаты (онлайн — позже) |
| promo | позже | промокоды и скидки |

## 5. Опыт похожих проектов (выводы)

- **WooCommerce / Shopify**: корзина — выдвижная панель (не отдельная страница), чекаут
  в один экран с шагами «контакт → получение → оплата», гостевой заказ, письма на каждом
  статусе; способы доставки с пунктами самовывоза. Берём: drawer-корзина, 1 экран чекаута,
  гостевой заказ, статусы и письма.
- **Calendly / YClients / Dikidi**: запись в 3–4 шага (услуга → дата → слот → подтверждение),
  буферы между записями, подтверждение письмом, перенос/отмена из кабинета. Берём: минимум
  шагов, слоты из расписания, письмо-подтверждение, кабинет.
- **Tilda / WordPress**: модульность и группировка админки, «включатели» модулей. Берём:
  реестр модулей и одну страницу управления.

## 6. Дорожная карта

- **P0 (сделано и проверено)**: страница 404; живой поиск в каталоге; липкая мобильная
  панель на карточке; хлебные крошки в каталоге; группы в админ-меню.
- **P1**: страница «Модули» (реестр + флаги) — следующий шаг ядра.
- **P2**: модуль «Запись» (календарь, слоты, буферы, подтверждение, кабинет, гость по коду).
- **P3**: модуль «Корзина и заказы» (услуги и товары, доставка/самовывоз, статусы, письма).
- **P4**: отзывы/рейтинг, комментарии; промокоды; онлайн-оплата; sitemap из БД; аналитика.

## 7. Правила, чтобы не перегружать

1. Новый функционал — только модулем по контракту §4; ядро не разрастается.
2. У клиента — минимум действий: одна кнопка на действие, гость без регистрации.
3. Один модуль = один пункт меню и одна страница-раздел; вложенное — внутри.
4. Все письма — через очередь; все флаги — в «Модулях»; всё состояние — в URL.
5. Каждый модуль можно выключить без следов на сайте (404 + скрытие меню).
