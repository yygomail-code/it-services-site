# CONTEXT.md — Проект: витрина ИТ-услуг с воронкой лидов

## Назначение
Персональный многостраничный сайт-витрина ИТ-услуг одного исполнителя. Работает как воронка для лидов:
- **Клиентская воронка** — посетитель → услуга → заявка → лид
- **Партнёрская воронка** — партнёр (дизайнер, маркетолог, студия…) → сотрудничество → лид-партнёр

Лиды приходят из соцсетей, Авито, фриланс-бирж и прямого трафика.

## Стек
| Слой | Технология | Примечание |
|---|---|---|
| Фронт | Angular (standalone, mobile-first) | Сборка с prerender → чистый HTML, Node на хостинге НЕ нужен |
| Бэк | PHP 8.5.6 | Почтовый шлюз лидов `api/lead.php` + API админки (auth/leads/content/users) |
| Админка | `/admin` (Angular, Client-render) | Роли client/manager/admin; лиды, контент, пользователи, настройки |
| Почта | Яндекс SMTP | Основной канал уведомлений (письмо) |
| Мессенджеры | НЕ подключаем | Только почта. Задел на будущее — интерфейс `Notifier` в PHP |
| БД | MySQL/MariaDB | Таблицы `leads`, `users`, `site_content`. Локально для разработки |
| Хостинг | Виртуальный сервер: PHP + MySQL + статика | Без Node |

## Ограничения среды
- На хостинге нельзя запустить Node — только Python, PHP, MySQL, HTML.
- Проект компилируется в статический HTML (Angular prerender/SSG).
- Фронт без своего бекенда в классическом смысле; PHP — только шлюз лидов.

## Структура сайта
```
/                  Главная (оффер, якоря, CTA)
```

## Партнёрские роли (воронка коллабораций)

2. Маркетологи / таргетологи / SEO-специалисты — партнёрская комиссия
3. Копирайтеры / контент-менеджеры — комплексные проекты
4. Веб-студии и малые агентства — субподряд / перегрузка
5. SMM-специалисты — реферальная комиссия
6. Бэкенд / мобильные разработчики — обмен и совместные проекты
7. (задел) Инфобизнес, биржи, ИП-бухгалтеры/юристы — реферальный канал

Форматы сделок: `referral` (партнёр приводит клиента → комиссия) и `outsource` (партнёр продаёт комплекс, мы — субподрядчик по коду).

## Модель лида (таблица MySQL `leads`)
```
id, lead_id (уникальный), lead_type (client|partner), partner_role, deal_type,
name, phone, telegram, service, message,
utm_source, utm_medium, utm_campaign, page,
status (new), notify_to, created_at
```
- `lead_type=partner` → заполняется `partner_role` и `deal_type`
- UTM-метки подставляются из URL автоматически (скрытые поля форм)

## Админка и роли
- `/admin/login` — вход (сессии + CSRF)
- **client** — учётка создаётся, доступа к админке нет
- **manager** — лиды: просмотр, фильтры, поиск, статусы (new/in_progress/closed/rejected), удаление
- **admin** — всё, что у менеджера + контент (тексты/цены), пользователи, настройки
- Контент хранится в `site_content` (ключ → значение), подставляется на сайт автоматически (ContentService)
- Пользователь по умолчанию: admin / admin123 (seed.sql)

## SEO

- JSON-LD: Organization, Person, Service, FAQ, BreadcrumbList
- sitemap.xml, robots.txt, canonical
- WebP/AVIF + lazy-load, Core Web Vitals (LCP < 2.5s)
- Яндекс.Метрика + цели по формам и телефону; Google Search Console

## Режимы работы
- `APP_ENV=dev` (локально): шлюз пишет в MySQL, письмо НЕ отправляет (чтобы не спамить при тестах)
- `APP_ENV=prod`: полный цикл — письмо на Яндекс + запись в MySQL
