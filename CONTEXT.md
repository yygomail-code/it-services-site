# CONTEXT.md — Проект: витрина ИТ-услуг с воронкой лидов

## Назначение
Персональный многостраничный сайт-витрина ИТ-услуг одного исполнителя. Работает как воронка для лидов:
- **Клиентская воронка** — посетитель → услуга → заявка → лид
- **Партнёрская воронка** — партнёр (дизайнер, маркетолог, студия…) → сотрудничество → лид-партнёр

Лиды приходят из соцсетей, Авито, фриланс-бирж и прямого трафика.

## Стек
| Слой | Технология | Примечание |
|---|---|---|
| Фронт | Angular (standalone, mobile-first) | Сборка с prerender → чистый HTML, Node на хостинге НЕ нужен |
| Бэк | PHP 8.5.6 | Почтовый шлюз лидов `api/lead.php` + API админки (auth/leads/content/users) |
| Админка | `/admin` (Angular, Client-render) | Роли client/manager/admin; лиды, контент, пользователи, настройки |
| Почта | Яндекс SMTP | Основной канал уведомлений (письмо) |
| Мессенджеры | НЕ подключаем | Только почта. Задел на будущее — интерфейс `Notifier` в PHP |
| БД | MySQL/MariaDB | Таблицы `leads`, `users`, `site_content`, `pages`, `services`/`service_categories`/`card_templates`/`service_media`, `email_queue`, `app_settings`. Локально для разработки |
| Хостинг | Виртуальный сервер: PHP + MySQL + статика | Без Node |

## Ограничения среды
- На хостинге нельзя запустить Node — только Python, PHP, MySQL, HTML.
- Проект компилируется в статический HTML (Angular prerender/SSG).
- Фронт без своего бекенда в классическом смысле; PHP — только шлюз лидов.

## Структура сайта

## Услуги
Каталог хранится в БД (модуль «Каталог», раздел админки `/admin/services`): цена, описания, медиа-галерея, группы (категории), шаблоны карточек, флаги (запись в календарь, продажа в магазине, комментарии, рейтинг), доступ по ролям. Публично: `/services` — каталог услуг с фильтрами по группам, поиском, 15 услуг на страницу и пагинацией; `/products` — отдельный раздел товаров (включается в админке); карточки позиций — `/services/:slug` и `/products/:slug` (галерея, цена, раскрываемое описание, адрес с картой в модалке, форма заявки).

## Партнёрские роли (воронка коллабораций)
1. Веб-дизайнеры (UI/UX) — «верстаю ваш макет в код»
2. Маркетологи / таргетологи / SEO-специалисты — партнёрская комиссия
3. Копирайтеры / контент-менеджеры — комплексные проекты
4. Веб-студии и малые агентства — субподряд / перегрузка
5. SMM-специалисты — реферальная комиссия
6. Бэкенд / мобильные разработчики — обмен и совместные проекты
7. (задел) Инфобизнес, биржи, ИП-бухгалтеры/юристы — реферальный канал

Форматы сделок: `referral` (партнёр приводит клиента → комиссия) и `outsource` (партнёр продаёт комплекс, мы — субподрядчик по коду).

## Модель лида (таблица MySQL `leads`)
```
id, lead_id (уникальный), lead_type (client|partner), partner_role, deal_type,
name, phone, telegram, service, message,
utm_source, utm_medium, utm_campaign, page,
status (new), notify_to, created_at
```
- `lead_type=partner` → заполняется `partner_role` и `deal_type`
- UTM-метки подставляются из URL автоматически (скрытые поля форм)

## Админка и роли
- `/admin/login` — вход (сессии + CSRF)
- **client** — учётка создаётся, доступа к админке нет
- **manager** — лиды (просмотр, фильтры, поиск, статусы, удаление) + раздел «Каталог» (услуги и товары: список, карточки, группы, шаблоны карточек, настройки разделов «Услуги» и «Товары»)
- **admin** — всё, что у менеджера + контент (страницы в канвас-редакторе, медиатека, формы, шапка/футер/бренд), пользователи, роли, почта, настройки
- Контент страниц хранится в `pages` (секции/колонки/блоки, редактор в админке); прочие тексты — в `site_content` (ключ → значение)
- Пользователь по умолчанию: admin / admin123 (seed.sql)

## Режимы работы
- Письма не теряются: заявка или уведомление ставится в очередь `email_queue` ДО отправки, при сбое SMTP попытки повторяются (5/10/15/20 мин, до 5 раз), затем письмо видно в админке («Почта» → «Очередь писем») с кнопкой «Отправить ещё раз»
- SMTP-сервисы настраиваются в админке («Почта»), письма о заявках уходят на адрес `MAIL_TO` из `.env`
- Очередь обрабатывается: при заходах в админку (троттлинг 5 минут), вручную из раздела «Почта», по cron (`php api/cron_email_queue.php`) или по ссылке из админки («Почта» → «Запуск по расписанию», `api/cron_email_queue.php?key=…` — для планировщиков, умеющих только URL)
- `APP_ENV=dev` (локально): полный цикл с записью в MySQL и очередью; реальное письмо уйдёт, только если в «Почте» настроен доступный SMTP (в dev обычно недоступен — письма ждут в очереди)
- `APP_ENV=prod`: то же + рабочий SMTP на боевом хостинге
